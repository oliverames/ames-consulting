# UI and UX Pass

**Date:** 2026-08-27
**Base commit:** `b45295b`

## Scope

This pass reviews the rendered homepage and every top-level route at desktop and mobile widths. It also covers light and dark themes, reduced motion, keyboard focus, dialogs, filters, forms, and nested missing routes.

The pass may change shared styles, browser behavior, and regression tests when measurements confirm a defect. It leaves page copy, portfolio content, publication policy, and deployment automation unchanged.

## Method

- Capture each top-level route at 1440 by 900 pixels and 390 by 844 pixels.
- Measure overflow, overlap, tap targets, image dimensions, heading order, and resolved focus and hover styles.
- Exercise the work filter, contact validation and disabled states, image and recommendation dialogs, carousel controls, the inbound prompt, and a nested 404 route.
- Reproduce each candidate before changing source, then run the full source and deploy artifact gates.

## Findings

### Fixed

| Priority | Finding | Measured failure | Resolution |
|---|---|---|---|
| Medium | The mobile primary navigation clipped its last link. | At 390 pixels wide, the navigation ended at x=374.4 while Contact extended to x=420.0. Its keyboard focus ring stayed clipped. At 320 pixels, the current Testimonials and Contact links were both outside the visible strip. | `header-scroll.js` now scrolls the current link and any focused link into the nearest visible position. |
| Medium | The skip link sat behind the sticky header. | On mobile, the focused link occupied y=12.0 to 59.6 while the opaque header occupied y=0 to 98.0. The link used z-index 10 and the header used z-index 100, so hit testing returned the site name instead of the skip link. | The skip link now uses z-index 200. |
| Medium | Contact deep links hid the form under the sticky header. | `/contact/?project=Photography%20and%20video#contact-form` placed the form at y=0.0. The header ended at y=80.5 on desktop and y=98.0 on mobile. | The contact form now reserves a seven-rem scroll margin. |
| Medium | The writing archive deep link hid its target under the sticky header. | `/blog/archive/#microblog` placed the section at y=0.0 at both tested widths, behind the same header. | Writing streams with IDs now reserve a seven-rem scroll margin. |

### Confirmed good

- All seven top-level routes returned 200 and kept the document width equal to the viewport at 1440 by 900 pixels and 390 by 844 pixels.
- The same routes produced no moderate, serious, or critical Axe findings in dark mode at either width.
- Visible heading sequences contained no skipped levels, and content images retained intrinsic dimensions.
- All five randomized homepage headlines were measured at 1440, 1024, 833, 832, 390, and 320 pixels. The hero height stayed stable, the headline never intersected the portrait, and no variant created page overflow.
- The work filter, contact validation and sending states, carousel controls, image viewer, recommendation dialog, and inbound prompt behaved correctly in desktop and mobile dark mode. Dialog controls measured at least 44 pixels in each dimension.
- A nested missing route returned the custom 404 page at both widths, kept its home link root-absolute, and produced no horizontal overflow.
- Keyboard traversal found visible three-pixel focus outlines across every top-level route. The clipped Contact link was the only focus-position failure.

### Refuted candidates

- The homepage body reported eight pixels more width than its viewport, but the document did not overflow. The extra width belongs to the intentionally negative-margin project strip, which clips and scrolls within its own container.
- Unloaded homepage and writing images were outside the horizontal lazy-load window. The requests did not fail, and the built-site image checks remain the authority for published asset completeness.
- The closed image viewer injects an image without a source or intrinsic dimensions. It is absent from layout until a source image opens, so it does not create a blank content image or layout shift.
- Immediately after empty contact submission, the first invalid field briefly crossed behind the sticky header during smooth scrolling. The browser settled it near the viewport center within 400 milliseconds at both tested widths, so no form-scroll change was needed.
